# Проверка источника PostXbot

18 августа 2026 года проверен публичный корень `https://max.postxbot.ru/`. Без уникального URL отчёта сервис возвращает `401 Unauthorized`, поэтому по одному домену нельзя получить статистику конкретного размещения.

На предоставленном скриншоте конкретная страница отчёта отображает показатель «За 24 ч: 5 069». Для реализации безопасного специализированного извлечения нужен полный адрес этой страницы из строки браузера: он содержит идентификатор, токен или путь отчёта, которые не видны на скриншоте.

## Контрольный отчёт

Пользователь предоставил адрес `https://max.postxbot.ru/watchpost/rZP5IHTIZiqZSNUGc1k1eg`. Публичная страница доступна без авторизации и в HTML содержит общий показатель `5069` с меткой `24 ч.`, а также карточки отдельных каналов. Для сохранения безопасности автоматическая коррекция должна применять общий показатель только к записи, для которой в отчёте найдено ровно одно размещение, либо к однозначно сопоставленной карточке канала. Для общих отчётов с несколькими каналами потребуется выбор поканального значения из структурированных данных страницы или ручная проверка.

Загруженная страница обращается к публичному API `https://maxapi.postxbot.ru/cabinet/v1/max/watchpost`. Серверно-отрендеренная HTML-разметка уже содержит общий показатель и карточки каналов, поэтому базовый разбор можно выполнить без внутренних ключей; параметры API дополнительно уточняются для поканального сопоставления.

Повторная загрузка контрольного URL в автоматизированной среде иногда остаётся на стартовом экране, хотя ранее браузер получил полный серверно-отрендеренный отчёт. Поэтому серверная реализация должна использовать HTTP-запрос с таймаутом и разбирать полученный HTML, а не зависеть от исполнения клиентского JavaScript.

Вторая контрольная ссылка пользователя: `https://max.postxbot.ru/watchpost/WpdjgXPFUdN0Fp4FGBy_3A`. На пользовательском скриншоте страница показывает `1753` за `24 ч.`, но в автоматизированной среде иногда остаётся на стартовом экране. Парсер должен использовать повторные HTTP-попытки и не считать кратковременно неполный ответ доказательством отсутствия 24-часового показателя.

При повторной проверке этот отчёт продолжает оставаться на динамическом стартовом экране в автоматизированном браузере, хотя пользовательская страница полностью отображает данные. Это подтверждает, что ошибка вызвана нестабильной загрузкой PostXbot на стороне серверного клиента, а не отсутствием показателя за 24 часа.
